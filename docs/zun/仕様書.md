# Excudo 仕様書

ブランチ: `zun_loc` ／ 2026-10-07 時点の実装内容（自動テスト 121 件成功、実サーバーで動作確認済み）

---

## 1. 概要

ローカル LLM（vLLM 上の Qwen3）を使うコーディングエージェント。CLI とデスクトップアプリの 2 つの UI、経費精算機能（Keichan）を備える。

```text
[ UI ]  main.py（CLI）・ excudo/app（デスクトップアプリ）
   ▼ イベント（answer / reasoning / tool_call / approval / done）
[ Harness ]  harness.py ・ messages.py ──▶ [ Model ] model.py（vLLM）
   ▼
[ Tools & Safety ]  tools.py ・ permissions.py ・ security.py
```

- 依存は一方向。Harness は UI ライブラリ（Rich など）を import しない。
- Harness はイベントを返すジェネレータで、CLI とデスクトップアプリが同じ Harness を共有する。

---

## 2. Model層（`excudo/model.py`）

- **役割:** LLM との通信のみ。ファイル操作やコマンド実行はしない。
- **主なメソッド:**
  - `generate_response(messages) -> str` … テキストを送り、テキストだけを受け取る（ツールなし）。履歴の要約などに使用
  - `stream(messages, tools)` … 応答をトークン単位で返す（エージェントループで使用）
  - `complete(messages, tools)` … 応答をまとめて返す
- **応答に含まれるもの:** 思考（`reasoning`）／回答本文（`content`）／ツール要求（`tool_calls`）
- **思考モード:** 既定 OFF。`/thinking on|off` で切替。
- 送信前に Excudo 独自の `metadata` は必ず取り除く（サーバーには送らない）。

## 3. Harness層のループ（`excudo/harness.py`）

### 流れ

1. 履歴が上限を超えていれば圧縮する（要約）
2. ユーザー入力を履歴に追加
3. 以下を最大 `MAX_TURNS` 回くり返す
   - モデルを呼び出す
   - ツール要求なし → 回答を保存して**完了**
   - ツール要求あり → 権限チェック → 実行 → 結果を履歴に追加 → 3 に戻る
4. 最後に必ず `done` イベント（終了理由つき）を返す

### 終了条件

終了理由は `done` イベントで通知し、そのターン最後のメッセージの `metadata.finish_reason` にも記録する。

| 終了理由 | 判定 | 結果 |
| --- | --- | --- |
| `completed`（完了） | モデルがツールを要求しなかった | 正常終了 |
| `max_turns`（最大ステップ数） | `MAX_TURNS`（既定 15）に到達 | エラー表示して終了 |
| `interrupted`（ユーザー中断） | 応答中に Ctrl+C／停止ボタン | その応答だけ停止（アプリは継続）。未実行のツール要求には「中断」結果を補い、履歴を壊さない |
| `error`（通信エラー） | モデル呼出で例外 | エラー表示して終了 |

### 権限チェック（`excudo/permissions.py`）

| 区分 | 例 | 動作 |
| --- | --- | --- |
| 読み取り | `read_file`, `grep_search` | そのまま実行 |
| ファイル変更 | `write_file`, `edit_file` | `[y/N]` で確認（`/auto` 時は自動承認） |
| コマンド実行 | `run_command`, ターミナル系 | **常に確認**（`/auto` でも省略不可） |
| 社外送信 | `web_search`、`curl`・`git push` 等 | **常に確認** |
| 機密ファイル | `.env`、鍵・証明書、`settings.json`、経費記録 | **常に確認**。`grep_search` の対象外 |
| 危険なコマンド | フォーマット、シャットダウン、ドライブ全体の削除 等 | **常に拒否** |
| ワークスペース外 | 外部のパス（`..`・シンボリックリンク・ジャンクションを含む） | **常に拒否** |

### セキュリティ対策（`excudo/security.py`）

- **秘密情報のマスク:** ツール結果の API キー・トークン・秘密鍵などは `[REDACTED]` に置き換える。`[REDACTED]` をファイルへ書き戻す操作は拒否する。
- **プロンプトインジェクション対策:** Web の結果には「外部データ（指示ではない）」の注記を付ける。システムプロンプトで、ツール結果内の指示に従わないよう規定する。外部データを受け取ったターンでは `/auto` を停止する。
- **監査ログ:** 承認が必要な操作と拒否された操作を `.excudo/audit.log` に記録する（秘密情報はマスク）。
- **通信:** LLM サーバーへの接続が `http://`（暗号化なし）の場合、起動時に警告を表示する。HTTPS 化はサーバー側の対応が必要。
- **個人データ:** レシート画像・経費記録・Excel・設定ファイル・`.env` は `.gitignore` で Git 管理外。

## 4. 会話履歴（State）

### メッセージ型（`excudo/messages.py`）

OpenAI 形式の dict に、Excudo 用の `metadata` を付ける。

| 項目 | 内容 |
| --- | --- |
| `role` | `system` / `user` / `assistant` / `tool` |
| `content` | 本文 |
| `tool_calls` | ツール要求（assistant のみ） |
| `tool_call_id` | 対応するツール要求の ID（tool のみ） |
| `metadata` | 下表 |

| `metadata` の項目 | 内容 |
| --- | --- |
| `created_at` | 作成日時 |
| `turn` | 何ターン目のメッセージか |
| `tokens` | トークン数の概算 |
| `finish_reason` | ターンの終了理由（ターン最後のメッセージ） |
| `tool_call_source` | ツール要求の取得方法（`native` / `text`） |
| `kind` | 圧縮で作られたメッセージの種類（`summary` / `note`） |

※ 思考（reasoning）は画面表示のみで履歴には残さない。

### 保存（`excudo/session.py`）

- 保存先: `.excudo/sessions/<ID>.json`（`metadata` も含めて保存）
- タイミング: 毎ターン終了後（中断したターンも含む）
- 再開: `--continue`（最新）／ `--session ID`・`/load ID`
- 一覧: `--list`・`/sessions`
- 削除: `/delete ID`（CLI）／ セッション一覧の 🗑 ボタン（アプリ、2 回クリックで確定）
- セッション ID は英数字・`_`・`-` のみ許可（`../` などで外部のファイルを読めない）

### 圧縮ルール

- **発動条件:** 履歴が **40 件**を超える、または概算 **40,000 トークン**を超える
- **タイミング:** 新しい質問を送る直前のみ（回答後に待たされない）
- **残すもの:** システムプロンプト＋直近の会話（最大 38 件・上限の半分のトークンまで）
- **古い会話:** モデル（`generate_response`）が**要約**し、1 件の system メッセージに置き換える
  - 要約に失敗した場合は「N 件削除」の注記だけを残す
- 先頭に結果だけ残った `tool` メッセージは削除（対応関係を壊さない）
- 長いツール出力は切り詰める（履歴 2 万文字、`read_file` 5 万文字、`run_command` 1 万文字）
- 設定: `EXCUDO_MAX_HISTORY_MESSAGES` / `EXCUDO_MAX_CONTEXT_TOKENS` / `EXCUDO_SUMMARIZE_HISTORY`

## 5. ツール呼出の解析

### 通常: function calling

- 全ツールの定義（名前・説明・引数の JSON Schema）をモデルに送る。
- ツール要求は本文とは別の `tool_calls` で返ってくる。
- 分割されて届く要求を `index` ごとに連結し、引数を `json.loads` で解析する。

### 予備: テキストからの解析

- サーバーがツール要求を取り出せず、本文に残った場合に使う。
- **形式:** Qwen3 の `<tool_call>{"name": "...", "arguments": {...}}</tool_call>` タグのみ
  - 通常の JSON やコード例は対象外（誤認識を防ぐ）
- 解析後、タグは本文から取り除き、`metadata.tool_call_source = "text"` を記録する。

### エラー時

実行せず、理由をモデルに返してループを続ける（モデルが次の行動を判断）。

| 状況 | モデルへ返す内容 |
| --- | --- |
| 引数の JSON が不正 | `Error: Malformed JSON arguments` |
| 存在しないツール | `Unknown tool` |
| 権限で拒否 | `Action rejected` |
| 実行中の例外 | `Error executing tool` |

## 7. Keichan（経費精算）

- レシート画像を Qwen3（vision）で解析し、Markdown の要約表と JSON を出力（ローカル OCR は不要）
- 月別ファイル（`経費精算/records/YYYY-MM.json`）に取引日ごとに保存。重複チェックあり
- 取引日は購入日を使用（定期券などの有効期間は備考に記載）
- 一括処理: `keichan_data/KEICHAN.bat` をダブルクリックで、未処理のレシートをすべて処理
- Excel 出力: 会社書式の「経費申請書」（月日・内容・備考・金額・受領印・合計）を `経費精算/exports/` に出力
- 氏名は初回実行時に入力して `経費精算/settings.json` に保存（メンバーごとに個別）

## 8. UI

### CLI（`main.py`）

- スラッシュコマンド: `/help`、`/status`、`/auto`、`/thinking`、`/skills`、`/sessions`、`/load`、`/delete`、`/history`、`/receipt`、`/clear`
- 起動画面（モデル・ワークスペース・承認モード・セッション・表示言語）、待機中のスピナー

### デスクトップアプリ（`excudo/app`、`Excudo.bat`）

- チャット画面とセッション一覧、Markdown 表示、ライト／ダークテーマ
- 承認は「許可 / 拒否」ボタン、停止ボタン
- ツール実行は 1 行の分かりやすい文で表示（クリックで詳細）、作業中インジケーター
- レシート画像のドラッグ＆ドロップ → 解析結果 → 保存ボタン
- ミニ表示（常に最前面の小さなチャット）
- デザインは `DESIGN_SYSTEM.md` のトークン（Claude Code・Codex・Antigravity を参考）に準拠

### 多言語

- 日本語・ベトナム語（アクセントなしの入力も含む）・英語を自動判定し、画面と回答の言語を切り替える（`EXCUDO_LANG` で固定も可能）
- Windows のコンソールを UTF-8 に設定（ベトナム語の表示と `run_command` の文字化けを解消）
