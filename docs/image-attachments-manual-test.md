# Python CLI 画像添付の手動確認

作業フォルダー内に `first image.png` と `second.jpg` を用意してCLIを起動する。
Ctrl+Jは改行、Enterは入力の確定に使う。

| 操作 | 期待結果 |
| --- | --- |
| `/attach "first image.png"` を確定し、別の入力で質問を送る | 送信枚数の行に停止した `0.0秒` の状態バーが重ならず、回答後も残らない |
| `/attach "first image.png"` → Ctrl+J → 質問 → Enter | 画像と質問が同じリクエストに含まれ、質問がパスとして扱われない |
| `/attach "first image.png" "second.jpg"` → Ctrl+J → 比較の質問 → Enter | 2枚を送信する |
| Windowsで `/attach ` の後に2枚を続けてドラッグしEnter | パスが引用符に隣接した場合や、ドライブ付きパス同士が隣接した場合も2枚に分割する |
| 2枚を選択後 `/detach 1`、続けて `/attachments` | 最初の画像だけを解除し、残った画像を番号1で表示する |
| `/detach 4`（画像が1枚の状態） | 存在しない番号を案内し、選択を変えない |
| `/detach *`、続けて `/attachments` | 選択が空になる。引数なしの `/detach` も同様 |
| 有効な画像を選択後 `/attach "missing.png"` → Ctrl+J → 質問 → Enter | `missing.png` を含むエラーを表示し、質問は送信せず、元の画像は保持する |
| `/attach "broken.png"`（画像ではない内容のファイル） | 対象パスと形式・破損エラーを表示する |

macOSでは最初の2項目を実際の端末で確認する。モデルの応答速度や内容の検証には実モデルを使い、モデルを置き換えたテストと区別する。

## クリップボード

- macOSのFinderで画像ファイルをコピーしてCtrl+Oを押す：`/attach` の利用を案内するエラーになり、ファイルのアイコンを添付しない。既存の添付は保持する。
- macOSでスクリーンショットを画像データとしてコピーしてCtrl+Oを押す：通常の画像として添付する。
- 4 MiBを超え20 MiB以下、1600万画素以下の画像データをコピーして貼り付ける：1280pxに縮小してから4 MiB上限を確認する。20 MiBを超える入力は拒否する。
- 貼り付け後も入力中の質問が残り、自動送信されないことを確認する。

関連する自動テスト：

```text
python -m pytest tests/test_attachments.py tests/test_cli_session_save.py tests/test_messages.py tests/test_request_policy.py -q
```

## デスクトップ

- 画像ファイルを選び、サムネイルの上下に同程度の余白があり、×が右上の角にそろうことを確認する。入力欄と各ボタンも縦方向にそろうことを確認する。
- 4枚を追加すると「画像を添付」が無効になる。1枚外すと再び有効になる。
- スクリーンショットをクリップボードにコピーし、会話欄、サイドバーのボタン、チェックボックスにフォーカスを移してCtrl+V（macOSは⌘V）を押す。画像が添付欄に追加され、自動送信されないことを確認する。
- 入力中の文字を選択してテキストを貼り付け、通常どおり選択部分だけが置き換わることを確認する。入力欄の外からテキストを貼り付けた場合は質問の入力欄に入る。
- 画像ではない内容のPNGを選ぶ。添付欄の近くにエラーが1つ表示され、約4秒後に消え、会話には残らないことを確認する。同じエラーを連続して起こしても重ならない。
- 回答生成中にも添付エラーを起こし、思考や回答の間にエラーの吹き出しが挿入されないことを確認する。
- 画像を添付して質問を送信し、ユーザーメッセージ内に画像と名前が残ることを確認する。回答を読んだあと、新しい会話へ移動して元のセッションを開き直し、画像が再び表示されることを確認する。
- 質問を入力せず画像だけを添付して送信する。回答を受け取り、セッションを開き直して画像が表示されることを確認する。文字も画像もない場合は送信されないことを確認する。
- 送信直後の会話内のサムネイルをクリックし、送信時の画像が大きく表示されることを確認する。画像・背景・閉じるボタンのクリック、Escで閉じられることを確認する。Tabでサムネイルを選び、EnterまたはSpaceでも開けることを確認する。
- セッションを開き直してサムネイルをクリックし、モデル送信時と同じ大きさ（最大1280px）の画像で文字を確認する。JSONのhistoryにimage_urlがなく、image_previewsには256px以下のJPEGと画像ファイル名だけがあることを確認する。大きい画像は `.excudo/sessions/<セッションID>/` の画像ファイルに保存され、クリックする前は読み込まれない。
- 同じセッションで3枚の画像を送信し、続けて別の画像と質問を送信してから開き直す。モデル用の古い画像が名前に置き換わっても、最初の3枚と次の画像のサムネイルがすべて表示されることを確認する。画像を追加しない質問を送った場合も確認する。
- アプリを終了して起動し直し、元のセッションを開いて同じ画像が表示されることを確認する。古いセッションですでに元の画像データが失われている場合は、復元せず`[画像: ファイル名]`を表示する。
- セッションを削除し、対応するJSONと画像フォルダーが両方消え、別セッションの画像は残ることを確認する。
- 画像ファイルがない古いセッションではサムネイルを拡大し、画像もサムネイルもない場合は名前だけを表示する。
- CLIで画像を送って保存したセッションをデスクトップで開く。履歴に残っている画像が表示され、拡大時に「縮小版」が付かないことを確認する。通常の保存画像、256pxのサムネイルしかない古いセッション、画像ファイルがなくなった場合にもこのラベルを表示しない。
