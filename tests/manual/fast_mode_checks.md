# 長考抑制・高速モードの確認

## 比較条件

同じ作業場所・新規会話・モデル・質問で、修正前、英語指示追加後、追加後の思考OFFを各1回測定する。
質問は「Pythonの歴史を詳しく説明してください。ツールは使わないでください。」。
ツールなしのストリーミングAPIで条件を揃え、ツール実行、サーバー設定変更、履歴要約は行わない。
自動再試行を無効化し、送信は許可された3回のみ。思考原文は保存せず、文字数と時間だけ集計する。
回答はローカルの検証用データで読み直し、主要な歴史的事実と説明のまとまりを比較する。
API測定と別に、CLI→Harness→ModelのON/OFFとAPI送信値は自動テストで確認する。

時間は送信開始から最初の思考、最初の本文、全受信完了を記録する。
思考表示時間は最初の思考から最初の本文までで、サーバー内部の計算時間ではない。
各1回のため、キャッシュ・負荷・生成の揺らぎを除外できず、平均速度や一般的な品質を保証しない。

## 実機確認

1. `/help` で `/fast` と `/fast off` が見えることを確認する。
2. `/fast` を送り、高速モードのオンが表示されることを確認する（この操作はAI送信なし）。
3. 「Pythonの歴史を詳しく説明してください。ツールは使わないでください。」と送る。
   思考OFFが対応サーバーへ渡される。本文内容も読み、単なる短縮・事実誤りがないか確認する。
4. `/think` は今回受信した思考がなければ「表示できる直前の思考はありません」。
   サーバーが思考OFFを無視して返した場合も、受信した内容を隠して成功扱いにしない。
5. `/new` 後も高速モードは維持する。`/fast off` を送って、次の質問が通常設定へ戻ることを確認する。
6. `/fast maybe` など未知の引数は案内だけを表示し、モードを変更したりAIへ送ったりしない。
7. CLIを再起動したら高速モードはオフへ戻る。
8. 高速モードでもコマンド承認・Ctrl+C停止・日本語入力・補完が従来どおりか確認する。
   承認と安全機構についての自動テストは実行済みで、危険なコマンドを実機で試す必要はない。

Windowsローカル全テスト：665 passed / 19 skipped（外部モデル送信なし）。
3OS CIは本体リポジトリのPRで実行する。今回のブランチはまだpushしていない。
未提出の小話・折り返し表示の変更は別作業場所に保持し、今回のブランチには含めない。

高速モード中のCtrl+C停止も含む最終ローカル全テストで確認済み。固定CLIデモの `/fast` → 回答 → `/think` → `/fast off` → 終了も外部通信なしで通過。

### 回答の正確さ

主要な転換点については説明があるが、3条件とも細部の事実誤りを確認した。

| 確認項目 | 修正前 | 指示追加後・通常 | 思考OFF |
| --- | --- | --- | --- |
| Python 3.0は2008年12月公開 | 合致 | 合致 | 10月と誤記 |
| PSF設立は2001年 | 2000年と誤記 | 2000年と誤記 | 設立年の記載なし |
| Python 2.7公開は2010年 | 合致 | 2007年と誤記 | 公開年の記載なし |
| Python 2終了は2020年1月1日 | 2020年1月と記載 | 2020年9月と誤記 | 合致 |
| リリース周期はPEP 602で年次化 | 2年ごと、PEP 595と誤記 | 周期は年次だがPEP 600と誤記 | 記載なし |

思考OFFには「リスト内包表記は1.4で導入」「raw文字列がPython 3で削除」という誤りもあった。
リスト内包表記はPython 2.0の新機能であり、raw文字列は現在も利用できる。

- Python 2.7公式リリース：https://www.python.org/download/releases/2.7/
- Python 2.0の新機能：https://docs.python.org/3/whatsnew/2.0.html
- raw文字列の仕様：https://docs.python.org/3/reference/lexical_analysis.html#raw-string-literals

正解率を数値化した網羅的評価ではない。記載なしを誤答扱いにはしていない。
今回の結果から「指示追加により正確になった」「思考OFFでも品質を落とさない」とは主張しない。
コード修正や計算など別タスクのモデル精度は、今回の許可範囲では測定していない。

### PR説明に使う要点

英語の長考抑制指示と `/fast`・`/fast off` を追加。高速モードはツール後の再応答にも適用し、
承認・安全機構は変えない。モード切替は会話履歴・セッションに入れない。
Windowsのローカル全テストは665成功・19スキップ。固定デモとCLI→Harness→APIの送信値も確認済み。
実モデルの各1回比較では、通常モードの思考は305.0秒・9,148文字から460.8秒・15,055文字へ増え、
プロンプトだけの短縮効果は確認できなかった。思考OFFは思考0文字、本文開始3.1秒、全体146.8秒。
回答内容の誤りは残り、品質維持は未確認。この制約を隠さず記載する。

新ブランチは `codex/fast-mode`。mainブランチ・サーバー設定は変更せず、コミット・pushは未実施。

高速モードの表示：入力欄は `FAST >`、処理中の状態バーにも `FAST` が出る。`/new` 後も維持し、`/fast off` で両方が通常表示へ戻る。狭い画面でも状態行が折り返されないことを確認する。

FAST表示とオフ候補の追加後：Windowsローカル全テスト680 passed / 19 skipped。疑似キー入力で `FAST >` 表示中の `/fast o` → Tab → Enter が `/fast off` として送信されることも確認済み。`/fast` の再入力はオンを維持する。追加のAI送信は行っていない。
