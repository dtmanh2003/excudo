# 表示レビューの実機確認

## 1. 同じ本文で描画だけを確認

```text
uv run python scripts/ui_debug_demo.py
```

起動後、`layout` を送信する。これは固定本文を流すデモで、実モデルや外部ツールは使用しない。

- 「不変」が太字で、括弧の補足も読める。
- FIRST・SECOND・THIRDの間に、原文にない空行が増えない。途中表示と確定後の両方を見る。
- 表の「説明末尾A」「説明末尾B」「説明末尾C」が読め、セルの途中が省略記号に置き換わらない。
- 端末幅を広げると表は100桁を超えて広がり、狭めるとセルが折り返される。
- コード内の `**literal**` は太字へ変換されず、コードとして残る。
- LAYOUT_DONEが表示され、次の入力へ戻る。

幅変更による表示済み履歴の再折り返しは既知の制限。新しく描画する部分の切れ・余分な空行と分けて記録する。

## 2. 実モデルにつないで確認

デモを終了し、`uv run main.py` で起動する。モデルへの送信が発生する。
`/new` を送ってから、次を送る。

```text
Pythonのlist・tuple・dict・setの違いを初心者向けに説明してください。ツールは使わないでください。
最初に「不変」という語をMarkdownの太字にし、その後に「（イミュータブル）」という補足を書いてください。
次に、項目間に空行を入れず、短い箇条書きを3項目書いてください。
続けて、list・tuple・dict・setを列にした比較表を作り、用途・変更可能性・ハッシュ可能性を比較してください。ハッシュ可能性の条件は省略せず説明してください。
最後に、これらを作成する短いPythonコードを付けてください。実行は不要です。
```

太字・表・箇条書き・コードを上の観点で見る。生成された内容の正確さも別に確認する。
未確定の表・コードが途中で本文として露出しないこと、段落は途中から表示されることも確認する。

## 3. 普段の入力操作

- 日本語を入力して変換・確定する。文字が消えず、IME確定だけで送信されない。
- `/he` を入力し、Tabで `/help` にする。Enterで送信する。
- `ex` を入力し、Tabで `exit` にする。送信せず消去する。
- 回答中に幅・高さを変更し、Ctrl+Cで停止して次の入力ができる。

## 記録

OS・端末名、使用コード、モデル接続の有無、端末サイズ、再現手順、画面の状態を残す。
Windowsの確認はMacの目視確認を代替しない。Mac担当者にも同じ手順で確認を依頼する。
固定デモ・自動テスト・実モデルでの実端末確認は、それぞれ別の結果として報告する。
