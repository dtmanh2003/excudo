# 候補選択後の入力欄の消し残し

## 確認範囲

上下キーで長いスラッシュ候補から短い候補へ移った際、入力欄の右側に前の文字が残り、次の入力で消えるというWindowsでの報告に対応する。
実端末の描画ずれそのものは自動テストでは再現できていない。候補選択後の画面だけに残像を置く模擬テストで、入力データを変えずに行末消去できることを確認する。

全画面の消去・Rendererのリセットは使わない。選択中のスラッシュ候補があり、カーソルが入力末尾のときだけ、描画後にカーソル右側を消去する。実際の後続文字がある場合は消去しない。

候補一覧を閉じた後に下側へ「る」などの文字が残る報告にも対応する。一覧が表示ありから非表示になったときだけ、描画後の下枠より下を消去し、入力カーソルを元へ戻す。

## 実端末の手順（モデル送信不要）

1. `uv run main.py` で起動する。
2. `/` と入力し、上下キーで候補を何周か選択する。
3. `/web_search` や `/load_skill` など長い候補から `/grep`・`/new` など短い候補へ移る。
4. 次の文字を入力する前の時点で、カーソル右側に以前の文字が残らないことを確認する。
5. `/` をBackspaceで消した場合とEscで候補を閉じた場合の両方で、一覧のあった領域に文字が残らないことを確認する。Escの場合は元の `/` が残り、通常の文章入力・日本語変換・削除ができることも確認する。
6. 幅を狭くして上下選択を繰り返し、Tab確定やEnter送信が従来どおりであることを確認する。試すコマンドは説明だけを出す `/grep` などにする。
7. 入力途中に本物の後続文字がある場合、その文字が消えないことを確認する。

候補がない状態の上下キー・複数行編集・IMEの既存動作は変更しない。元の症状が出にくいため、実端末で複数回確認し、残像が出た場合はスクリーンショットと操作順を記録する。

## 提出の分離

小話（#28）、Backspace後の候補再表示（#27）、高速モード（#26）は含めない。

## 確認結果

Windows実端末で、入力欄の右側の消し残しの解消と、候補一覧を閉じた後の追加修正を確認済みとの報告を受けた。
