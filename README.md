# Excudo

Excudo is a local coding agent that runs on a Qwen3 model served on your own machine or network through vLLM. It uses a Model/Harness design: the Model only talks to the LLM, and the Harness owns the conversation, runs tools, and checks permissions before anything is changed.

It ships with three front ends: a desktop app (pywebview), a React/Ink terminal UI, and a plain CLI. It also includes Keichan, a tool that reads receipt images and exports a monthly expense report to Excel.

## About this project

Excudo was built by a team of five during an internship, and is published here with the company's permission. This repository is a single snapshot of my development branch, which combines the team's main branch with my own work. The full commit history is not included, to keep teammates' work email addresses private.

My part of the work (Duong Manh):

- **Desktop app**: image attachments (file picker, drag and drop, Ctrl+V paste), image previews kept across sessions, `/` tool list in the chat input, title bar and logo, and merging the team's visual design with the current app logic
- **Keichan (receipt reader)**: reading and confirming receipts inside Excudo, showing results as they arrive, and exporting monthly expense reports to Excel
- **Tools**: `apply_patch` for multi-file edits, `list_dir`, `delete_file` with a mandatory confirmation step, Playwright browser tools, and porting the code intelligence, secret scan, Git remote, host terminal and CI check tools from a teammate's branch
- **Integration**: combining the reviewed main backend, the React/Ink UI and the desktop app into one branch, and running every test in a temporary workspace
- **Language**: splitting UI text into per-language files

## Requirements

- Python 3.13 and [uv](https://docs.astral.sh/uv/)
- A vLLM server running a Qwen3 model. Set its address in `EXCUDO_BASE_URL` (in the environment or in `.excudo/launcher-env.json`); there is no built-in default.
- Windows for the `.bat` launchers. The CLI also runs on macOS and Linux.

Copy `.env.example` to `.env` for optional settings such as web search.

## 画像を添付して質問する

画像をコピーして、入力欄で **Ctrl+O** または `/paste` を使うと、次の質問に添付できます。
貼り付けるたびに未送信の添付画像を最新の1枚に置き換えます。繰り返し押しても画像は増えません。
クリップボードでファイルを選択する場合も、画像は1枚だけ選択してください。
macOSのFinderでコピーしたファイルは、アイコン画像の誤添付を防ぐためエラーにします。`/attach` でファイルを指定してください。
スクリーンショットなどの画像データは、入力20 MiBまで受け付け、`/attach` と同じく1280pxに縮小してから1枚4 MiBの上限を確認します。
Ctrl+Vも受け付けますが、ターミナル側がこのキーを処理する場合はCtrl+Oを使用してください。
貼り付け操作は入力中の質問を送信しません。画像を添付してから質問を入力し、Enterで送信します。
端末内では画像の名前・枚数を表示します。画像のサムネイル表示には対応していません。

ファイルから選ぶ場合は、作業フォルダー内の画像を指定します。

```text
/attach "screenshots/error screen.png"
この画面のエラーを説明してください。
```

`/attach` の行の後に Ctrl+J で改行して質問を書き、Enterで画像と質問を一度に送信できます。
`/attach` だけでEnterを押した場合は画像を添付し、次の質問を待ちます。

複数の画像は1行に並べて指定します。`/attach` の後に画像をドラッグしてパスを入力することもできます。

```text
/attach "screenshots/first image.png" "screenshots/second.jpg"
```

Windowsでは、ドラッグで隣接して入力された絶対パスも分割します（例：`C:\images\first.jpg"C:\images\second image.png"`）。
空白を含むパスは引用符で囲んでください。実際のドラッグ＆ドロップ対応は端末に依存します。
同じ入力の2行目以降は質問です。画像を追加する `/attach` コマンドは、別の入力としてEnterで確定してください。
`/attachments` で送信前の画像と番号を確認できます。`/detach 1`〜`/detach 4` で指定した画像だけを解除し、残った画像は1から番号を振り直して表示します。
`/detach *` または引数なしの `/detach` で全解除できます。`/new` でも未送信の添付を解除します。
添付した画像は次の質問で1回だけ追加され、その後は会話履歴の一部として保持します。
次の質問を送る際、過去の画像は最新の1枚を除いて `[画像: ファイル名]` に置き換えます。新しい画像を送る際は過去の画像をすべて置き換えます。
端末内では画像の名前・枚数を表示します。画像のサムネイル表示には対応していません。
画像ファイルを端末へドラッグしてパスが入力された場合も、そのパスだけでEnterを押すと添付できます。

対応形式は静止画のPNG・JPEG・WebPです。入力ファイルは1枚20 MiB・1600万画素までです。
長辺が1280pxを超える画像は縮小し、縮小後は1枚4 MiBまで、1回の質問につき4枚・合計8 MiBまでです。
画像の中身を検証し、破損した画像、作業フォルダー外・機密ファイル・リンク経由のファイルは添付しません。
添付に失敗した場合は対象のパスと理由を表示し、すでに選択していた画像を保持します。同時入力した質問は送信しません。
クリップボードのファイル選択にも同じ制限を適用します。Linuxの画像貼り付けには `wl-paste` または `xclip` が必要です。

画像は質問送信時に設定済みのモデルへ送信され、`.excudo/sessions/` に画像データを含む会話履歴として保存されます。
画像内の文字や秘密情報は自動マスキングされません。共有してよい画像を選択してください。
画像を理解できるモデルが必要です。画像を含む履歴が大きくなり、既存の16 MiBの保存上限を超えた場合は、保存エラーを表示します。

## 現在の日時

`get_current_time` は端末の時計から、日時・曜日（ISO: 月曜1〜日曜7）・UTCオフセットを返します。
`timezone` は `Asia/Tokyo`、`Asia/Ho_Chi_Minh`、`UTC` などのIANA名を指定でき、
省略時の `local` は端末の現地時間です。夏時間と日付の繰り上がりも反映します。
APIキーや実行承認は不要で、時計の変更やネットワーク通信は行いません。
端末の時計が誤っている場合は結果も誤ります。WindowsでもIANA名を使えるよう `tzdata` を同梱依存にしています。

日付付きの予定を別の時間帯へ換算するときは `convert_timezone` を使います。
`datetimes` にISO日時を1〜20件、`from_timezone`・`to_timezone` にIANA名を指定します。
例：`2026-10-23T12:00:00` を `America/Chicago` から `Asia/Ho_Chi_Minh` へ変換すると、
`2026-10-24T00:00:00+07:00` になります。夏時間・翌日への繰り越しも計算します。
夏時間の切替で存在しない時刻は拒否し、重複する時刻には明示的なUTCオフセットを求めます。
通信・承認は不要です。出典の時間帯を確認できない場合は推測せず、不明と伝えます。


## Web検索の設定

`web_search` は検索結果のタイトル・公開HTTPS URL・概要を返します。
キー未設定ならDuckDuckGoのHTML検索を利用し、追加パッケージやAPIキーは不要です。
既定の `auto` は、従来どおりBraveキーが設定済みならBraveを使用します。
検索先を固定する場合は、プロジェクト直下の `.env` または環境変数に設定してください。

```dotenv
EXCUDO_SEARCH_PROVIDER=duckduckgo
# Braveを使う場合は EXCUDO_SEARCH_PROVIDER=brave と BRAVE_SEARCH_API_KEY を設定
```

`.env` は起動時に自動で読み込まれます。変更後はExcudoを再起動してください。
設定済みの環境変数がある場合は、その値を優先します。
DuckDuckGoを明示指定すると、Braveキーがあっても使用・送信しません。
`.env` はGitの管理対象外です。共有するのはキーを空にした `.env.example` のみです。

APIの利用料金・無料クレジット・支出上限は
[Braveの管理画面](https://api-dashboard.search.brave.com/)で確認・設定してください。
検索語は選択した1つの検索先へ送信され、CLI・デスクトップの両方で毎回承認を求めます。
認証情報と思われる検索語を送信前に拒否し、応答は512 KiB、表示は約12,000文字、ワーカーは15秒までに制限します。
URL取得と同じ公開IPへの固定接続・TLS検証を使用し、リダイレクト・Cookie・プロキシ継承を行いません。Stopで中断できます。
DuckDuckGoはCAPTCHAやアクセス制限を返す場合があります。該当時はエラーを表示し、自動再試行や別の検索先への切替は行いません。
Wikipedia等の限定的な検索結果を、一般Web検索に成功した結果として返すこともありません。

## URLの本文取得

`fetch_url` は公開HTTPS URL（443番ポート）のHTML・プレーンテキストを読み取ります。
既存の `web_search` と異なりページ本文を取得し、APIキーは不要です。自動承認モードでも毎回承認します。
検出した認証情報を含むURL、内部ホスト名、DNSが返したプライベート・ローカル・特殊IPを拒否します。
検証済みのIPだけに接続し、元のホスト名でTLS証明書を検証します。プロキシ・Cookie・認証情報は引き継ぎません。
リダイレクトは最大3回まで追跡し、各転送先にもHTTPS・公開IP・認証情報なしの検証を適用します。HTTPへの転送・ループ・上限超過を拒否し、取得結果には最終URLも表示します。
大きなページも先頭の512 KiBから本文を取り出し、結果にページの途中で読み取りを打ち切ったことを表示します。読み取りは打ち切り検出用の1バイトを含め最大512 KiB+1バイト、解析対象とgzip展開後のデータはそれぞれ512 KiBまでです。連結されたgzipも合計で制限し、制限により止めた場合は部分的な本文として返します。制限に達していない壊れたgzip・途中切れ・未対応の圧縮形式は拒否します。ページの読み取り打ち切りと、返す本文の文字数による省略は別々に表示します。
本文は既定6,000文字・最大20,000文字、ワーカーは15秒までです。Stopでワーカーを終了できます。
本文からscript/style、ナビゲーション、関連記事の欄等を除き、表は列の対応を保って返します。
サーバーから分割送信されるHTML（React streaming SSR）も静的テキストとして読み取り、移動用scriptは実行しません。
ページのタイトルや時刻属性も未検証の外部データとして返します。JavaScriptを実行せず、PDFやバイナリを保存・処理しません。
取得した本文は信頼しない外部データとして扱い、既存のマスキングと追加承認を適用します。
サイトのログインやCAPTCHAには対応せず、取得失敗後の別手段による自動再取得は行いません。
## ファイル変更の記録

`get_agent_changes` は、現在の会話で `write_file`・`edit_file`・`apply_patch`・`delete_file` が変更したファイルを、変更ID・操作・パス・変更前の内容の保存状態とともに一覧表示します。既定20件、`offset`（1始まり）と`limit`（最大50）で続きを確認できます。承認を拒否した操作や、内容が変わらなかった操作は記録しません。

変更前の内容はRAM内だけに保存します。1ファイル2,000,000バイト、会話全体50,000,000バイト、履歴500件までです。大きなファイルや上限超過は保存できない理由を表示し、追跡できない場合は一覧が不完全な可能性を警告します。通常のファイルだけを対象とし、機密ファイル・領域外・リンク・複数のハードリンクを持つファイルをsnapshotのために読みません。内容・hashは一覧やモデル送信用履歴・sessionファイルに含めません。

新規会話、保存sessionの読み込み、アプリ終了で記録は失われます。保存済みのツールカードからsnapshotを復元せず、別の会話と共有しません。Bash・外部プログラム・手動操作・フォルダー作成は追跡対象外です。既存の削除承認と警告はそのままです。

`undo_change(change_id)` は、現在の会話の保存状態を使って変更を1件戻します。作成したファイルは削除、削除したファイルは再作成、編集は元のbyte列とmodeに戻します。ACL・拡張属性・更新日時までは復元しません。対象と操作を表示し、自動承認中も毎回確認します。外部の内容がある会話では追加確認が必要です。実行直前にも内容・mode・パスを検証し、手動編集・リンク・保存上限超過・古いID・後続の変更がある場合は拒否します。同じファイルは新しい変更から順に戻してください。完了した記録は`UNDONE`になり、復元の状態を検証できなかった記録は`UNCERTAIN`として再実行を止めます。

`rollback()` は、現在の会話の`ACTIVE`な変更をまとめて戻します。全ファイルの状態と変更の連続性を先に検証し、手動編集が途中に挟まる場合や不完全な履歴は開始前に拒否します。`UNDONE`・`ROLLED_BACK`は対象外です。自動承認中も対象一覧を確認し、全ファイルを再検証してから実行します。復元中のエラーやStopでは、処理済みのファイルを実行前の状態へ戻す補償処理を試みます。その間に外部で編集されたファイルには上書きせず、回復できなかったパスを明示して`UNCERTAIN`にします。複数ファイル全体をOSの1操作で切り替えるものではなく、完全な原子性は保証しません。補償用の内容もRAM内だけで最大50,000,000バイトに制限し、上限を超える場合は変更前に拒否します。

## コードの理解（code_*、branch zun_loc から）

作業フォルダーの Python ソースを読み取り専用で解析します。コードは実行しません（標準ライブラリの AST による静的解析）。

| ツール | 内容 |
|---|---|
| `code_symbols` | 関数・クラス・変数を名前や種類で探す |
| `code_structure` | 1つのファイルのクラス・関数の構成 |
| `code_definition` | 指定した位置（行・列）の名前の定義 |
| `code_references` | 指定した位置の名前が使われている箇所 |
| `code_call_graph` | 呼び出している側・呼ばれている側（静的な呼び出しのみ） |
| `code_index_status` | 読み取れたファイル数・読み取れなかったファイルと上限 |

いずれも承認不要（SAFE）ですが、結果は外部データとして扱います。リンク・ハードリンク・機密ファイル・`.git` や `.venv` などは読みません。
上限は `EXCUDO_MAX_CODE_FILES`（既定1000）・`EXCUDO_MAX_CODE_SYMBOLS`（既定30000）・`EXCUDO_CODE_TIMEOUT`（既定15秒）などで変更できます。対応言語は Python のみです。

## 作業の確認・Git・ターミナル（branch zun_loc から）

| ツール | 内容 | 承認 |
|---|---|---|
| `secret_scan` | ファイルに書かれた鍵・パスワード・社内アドレスの場所（値は表示しない。`.env` などは一覧だけ） | 不要（SAFE） |
| `get_logs` | `.log` ファイルの最後の行（機密情報は伏せる） | 不要（SAFE） |
| `inspect_image` | 作業フォルダーの画像を設定済みのモデルで確認する | 不要（SAFE） |
| `check_command` | git・node などがインストールされているか（実行しない） | 不要（SAFE） |
| `search_docs` | 公式ドキュメントのサイトに絞った検索 | 毎回確認（EXTERNAL） |
| `git_fetch` / `git_pull` / `git_push` | リモートとのやり取り。pull は fast-forward のみ。push は現在のブランチだけ、強制pushなし。送信するコミットに鍵・パスワード・社内アドレス・機密ファイルがあれば push しない | 毎回確認（EXTERNAL） |
| `git_revert` | 指定したコミットを取り消すコミットを作る | 確認（EXECUTE） |

| `ci_info` / `ci_workflows` / `ci_validate` / `ci_check` | GitHub Actions・GitLab CI の設定ファイルを読み取り・検証する（実行・送信しない） | 不要（SAFE） |

`EXCUDO_UTILITIES=dev` を設定すると、branch zun_loc の開発用ツール（`excudo/utilities/dev`）も使えます：
Docker（`docker_*`・`container_check`）、SQLite（`database_*`・`migration_status`）、API（`api_request`・`api_check`・`inspect_openapi`）、
依存関係（`dependency_*`・`check_dependencies`・`outdated_dependencies`・`add/update/remove_dependency`）、`security_scan`・`security_check`。
読み取りだけのツールは承認不要、コンテナ・データ変更・依存関係の変更は毎回確認（EXECUTE）、通信するものは外部送信として毎回確認（EXTERNAL）です。
本番データベースは対象外で、データを変更できるのは `EXCUDO_DATABASE_PROFILES` で開発・テスト用に指定した SQLite だけです。

ターミナル（`open_terminal`・`run_terminal_command`・`read_terminal`・`send_terminal_input`・`list_terminals`・`close_terminal`）は、
branch zun_loc と同じく既定では無効です。Windows で `EXCUDO_ALLOW_HOST_TERMINAL=1` を設定した場合だけ使えます。
cmd.exe を PC 上で直接動かすもので、OS による隔離はありません。コマンドや入力は毎回確認し（自動承認でも実行しません）、
危険なコマンドは拒否、通信するコマンドは外部送信として確認します。出力の機密情報は伏せます。zun_loc の QEMU VM 内のターミナルは含みません。
`run_command` と `grep_search` は、同じ働きの `bash_exec`・`grep` があるため追加していません。

## ブラウザー操作（Playwright）

エージェントが実際の Web ページを開き、読み取り、クリック・入力するためのツールです。依存関係は `browser` extra で追加します（`Excudo.bat`・`Excudo-Ink.bat` は追加済み）。

```text
uv sync --locked --extra browser
uv run --extra browser main.py
```

ブラウザーは、PC にインストール済みの Microsoft Edge、Google Chrome の順に使い、どちらもない場合は Playwright の Chromium を使います。
Edge か Chrome があれば、ブラウザー本体の追加ダウンロード（`uv run --extra browser playwright install chromium`）は不要です。
使うブラウザーを固定する場合は `EXCUDO_BROWSER_CHANNEL=msedge`（または `chrome`）を設定します。

| ツール | 内容 | 承認 |
|---|---|---|
| `browser_open` | http/https のページを開き、画面の状態を返す | 毎回確認（EXTERNAL） |
| `browser_click` | 画面の番号の要素をクリックする | 毎回確認（EXTERNAL） |
| `browser_fill` | 入力欄・選択欄に入力する（`submit` で Enter 送信） | 毎回確認（EXTERNAL） |
| `browser_read` | 開いているページの状態を読み取る（再読み込みなし） | 不要（SAFE） |

画面の状態は、タイトル・URL・番号付きの操作できる要素・表示中の文章（最大4,000文字）です。
クリックと入力は、この番号で要素を指定します。CLI の承認画面には、番号がどの要素か（例：`button "送信"`）を表示します。
操作の直前に、その要素が承認時に表示したものと同じか（同じページ・同じ説明）を確認し、変わっていれば操作しません。

- ブラウザーは毎回新しいプロファイルで起動します。保存済みのログインや Cookie は使いません。ダウンロードと Service Worker は無効です。
- 開けるのは http/https の URL だけです。localhost・社内のIPアドレス・`.local`/`.corp` などの社内の名前と、社内のIPアドレスを指す名前は開きません。リダイレクト先も1段ずつ確認します。
- 鍵・トークン・パスワードや社内の情報を含む URL・入力は送信しません。パスワード欄・支払い欄・ワンタイムコード欄・カード番号らしい数字・ファイル選択には入力しません。利用者が自分で入力します。
- 入力欄の値はモデルへ返しません。
- ページの内容は外部データとして扱います。`browser_read` も含め、結果には外部データの注記を付け、そのターンの自動承認を止めます。
- 画面を表示して動作を確認する場合は `EXCUDO_BROWSER_HEADLESS=0` を設定します。ローカルのページを試す場合だけ `EXCUDO_BROWSER_ALLOW_LOCAL=1` で localhost を許可します。
- 確認した名前がブラウザーの接続時に別のIPアドレスを返す（DNS rebinding）場合までは防げません。

## 安全機構

- ファイルツールは起動時の作業フォルダ内に限定し、リンク先も確認します。
- `.env`、鍵ファイル、`.git`、`.ssh`、`.aws` などはファイルツールからアクセスできません。
- 登録済みツールの結果に含まれる設定済みのBrave/OpenAIキーをマスキングします。
- Bashの子プロセスには PATH など必要な環境変数だけを渡し、キー・トークン・パスワードなどは渡しません。
- ツール関数内の例外はエラー文字列として返します。Harness は不正な JSON 引数も結果としてモデルへ返します。
- PermissionGate は領域外のパスを承認なしで拒否します。ファイルの作成・編集は承認を求め、`/auto on` で自動承認できます。
- CLI・デスクトップの削除承認画面は赤い枠と、この会話の間は保存状態により `undo_change` で戻せる場合があることを表示します。復元を保証するものではありません。
- `delete_file` はファイルを1つ削除します。復元用の保存ができない場合もあるため、自動承認が有効でも毎回承認を求めます。フォルダー・リンク・機密ファイル・作業フォルダー外は削除できません。
- 外部の内容を読んだ後の削除は、CLIでは `yes` の入力、デスクトップでは追加の確認チェックが必要です。
- Bash 実行と web_search は、自動承認が有効でも毎回承認を求めます。

実行前の承認は Harness / PermissionGate に実装済みですが、BashのOS隔離は未実装です。Bashは別の場所へ移動したり、
ファイルを読み書きしたりでき、ファイルツールの制限はBashには適用されません。
機密ファイルの判定とマスキングは限定的であり、すべての機密情報を検出するものではありません。
CLI の引数表示はマスキングします。モデルが生成する回答全体の秘密検出を保証するものではありません。

## Layout

- `excudo/model.py` — thin LLM client wrapper (no side effects)
- `excudo/harness.py` — agent loop: streams the model, assembles tool
  calls, executes them, feeds results back
- `excudo/messages.py` — message metadata and API serialization
- `excudo/session.py` / `excudo/storage.py` — session persistence and atomic writes
- `excudo/permissions.py` — workspace boundary and approval decisions
- `excudo/tools.py` — pluggable tool registry (add a tool = add a `Tool(...)`
  entry, no changes needed elsewhere)
- `excudo/browser.py` — Playwright browser tools (one dedicated browser thread)
- `excudo/skills.py` — discovers and loads `skills/<name>/SKILL.md` files
- `main.py` — CLI entry point (Rich-based, Japanese-facing UI)
- `skills/` — drop-in skill definitions, loaded on demand via the
  `load_skill` tool

## 回答のストリーミング表示

起動は `uv run main.py` です。UIはPythonのRich / prompt_toolkitを使用します。
受信中の本文は状態バーとは別の本文領域で、文の途中から逐次表示します。空行で段落をMarkdownとして履歴へ追加し、コードブロックは閉じた時点、表は空行または次の通常文で確定します。
確定した履歴は描き直さず、未確定の本文（末尾最大16行）と状態だけを更新します。ツール通知・エラー・終了の前に受信済みの本文を確定します。
パイプ出力では途中表示の制御文字を出さず、確定した段落を順次出力します。
補完候補はEnterで入力へ確定し、次のEnterで送信します。Tabで確定済み、または完全なコマンドならEnter一回で送信できます。

UIの担当箇所は `main.py`（入力・ロゴ・通知）、`excudo/markdown_stream.py`（段落の区切り）、`excudo/stream_preview.py`（受信途中の表示）です。
`uv run python scripts/ui_debug_demo.py` で実モデルを使わず表示・Ctrl+Cを確認できます。

通常の本文は左右に余白を置き、最大100桁で折り返します。表は端末の利用可能な幅を使い、長いセルは省略せず折り返します。段落間は空行で区切り、Markdownの見出し・箇条書きを維持します。表示上の折り返しなので、文章やコード自体の改行は変更しません。

`uv run python scripts/ui_debug_demo.py` で起動して `layout` と入力すると、実モデルへ接続せず、太字・空行のない箇条書き・長いセルを含む表・コードの途中表示から確定表示への切り替えを確認できます。実モデルでの操作確認を置き換えるものではありません。


### 回答中に履歴を読む（従来のWindows CMD）

上へスクロールして出力カーソルが画面の下へ隠れると、画面更新を保留します。
本文・状態・ツール通知は受信を続けて保持し、スクロールバーを下まで戻すと順番に表示します。
読み返している間は、回答完了後の次の入力欄も保留します。
Windows Terminal / ConPTYでは、このWindows APIによるホストのスクロール位置取得には対応していません。


### 起動画面と入力欄

起動時の枠内に、元のビーバーロゴ・操作ガイド・作業フォルダー・登録ツール数を表示します。
95桁以上は左右に配置し、狭い端末では縦に並べます。
入力欄は上下の細線で区切り、`/`の候補は下側にコマンド名と日本語の説明を最大8件表示します。
上下キーで選択し、EnterまたはTabで確定、Enterで実行します。選択が下へ進むと候補一覧も追従します。
この配置は `excudo/input_layout.py` が担当し、入力編集・履歴検索・複数行入力はprompt_toolkitの既存処理を使います。


### ツール実行中の停止

Harnessから実行するBashコマンドは0.1秒ごとに停止要求を確認します。
Windowsでは非対話プロセスとして起動し、CMDの入力を引き継ぎません。
Ctrl+Cによる停止時・タイムアウト時は、このツールが起動したPIDとその子プロセスを終了させます。
切り離されたプロセスなどは終了できない場合があります。既に行われたファイル変更は取り消しません。
ファイル検索も走査中に停止確認を行います。外部APIの通信待ちなどは、各処理のタイムアウトまで待つ場合があります。

LLMの受信中の停止は、次のチャンクを受け取ったワーカーが処理します。初回応答前や通信が途絶えている場合は、通信タイムアウトまで待つことがあります。


## 共通のAI指示

共通のAI指示は `excudo/prompts.py` で管理します。`main.py` は起動時に
`build_system_prompt()` を呼び、作業ディレクトリを含む指示をHarnessへ渡します。
作業別の `skills/*/SKILL.md` は、モデルが `load_skill` を呼び出したときに読み込みます。

「こんにちは！」「こんちゃ！」「ばんちゃ！」「konnnitiha!」「hello」など、本文全体が対応する挨拶だけの場合は、
最初の応答に限り `chat_template_kwargs.enable_thinking=false` を送信します。
この応答にはツール定義を渡さず、固定の挨拶スキル形式を使わないよう指示し、AIが返答を生成します。
判定では半角・カタカナ、伸ばし表現、末尾の記号や絵文字、複数の挨拶などの表記ゆれを
ローカルで吸収します。追加のAI判定は行いません。未知の表現は通常処理へ戻します。
挨拶に質問や依頼が続く場合、ツール実行後の再応答、通常の回答や履歴要約では、
高速モードを使わない場合は従来どおり思考設定を指定しません。判定は `excudo/request_policy.py` で管理します。

## 思考中の状態表示

思考用テキストの受信中は、同じ状態バーに `思考中 · 1,234文字 · 12.0秒` のように表示します。
文字数はその依頼で受信した思考用テキストの累計で、進捗率や残り時間を示すものではありません。思考本文のプレビューと保持は、下の「思考の表示」を参照してください。

## 既知の表示上の制限

ウィンドウの幅を変更すると、表示済みの回答（表や罫線など）が端末側で折り返し直され、表示が崩れることがあります。
ウィンドウをドラッグしてサイズを変えると、入力欄の表示が残ることがあります。

## 思考の表示

思考中は、思考の最初の文字を受信してから10秒以上経過し、かつ500文字以上受信した場合だけ、状態バーの上に最新の1行を薄い色で表示します。条件未満でも文字数・時間は表示し、`/think` で直前の全文を確認できます。回答本文が始まるとプレビューは消します。長い行は左側を省略して末尾を表示するため、直近に受信した部分を追えます。
回答後には `▸ 思考のメモ（30.0秒・1,234文字） /think で表示` の案内を残します。
`/think` で直前の依頼の思考全文を薄い色のプレーンテキストとして表示できます。全文の前後には薄い区切りを入れます。追加のAI送信は行いません。
思考の秒数は、最初の思考文字の受信から本文受信・承認待ち・ツール結果通知までの時間を合計したものです。サーバー内の計算時間や最初の受信までの待ち時間ではありません。

思考本文は画面用メモリだけで保持し、モデルへ送る会話履歴やセッションファイルには追加しません。
次の依頼・`/new`・CLI終了で破棄されるため、再起動後は表示できません。停止・エラーで終了した依頼は「途中まで」と表示し、受信済みの部分だけを確認できます。
思考データがない応答では案内は表示しません。秘密情報のマスキングと端末制御文字の除去を適用します。
`/think on` の常時表示は今回の対象外です。

思考の本文はモデルから受信した原文を表示します。追加の翻訳や日本語での再生成は行いません。

思考の受信中は30秒ごとに一言を更新し、次の更新まで表示を残します。20種類の物語から依頼ごとに1組を選び、30秒から240秒までの8段階で話が続きます。4分を超えても、その物語専用の余話を繰り返します。直前と同じ物語は避けます。文言は `excudo/waiting_stories.py` にまとめています。
待機の小話が表示された依頼では、本文受信時に同じ物語の受信用台詞へ切り替えます。台詞は通常の明るさで `Excudo：「…」` と表示します。完了・停止・承認待ちでは表示しません。
既存の描画更新を使い、追加のAI処理・タイマー・スレッドは作りません。
一言は進捗率や残り時間を示すものではなく、思考の原文や会話履歴には追加しません。
小話は状態バーとは別の一時表示領域で折り返し、狭い幅でも全文を表示します。思考プレビューは薄い1行のまま、文字数・時間は状態バーに残します。画面の高さに収まらない場合だけ小話の末尾を省略し、広げると全文を再表示します。

## 高速モード

`/fast`（または `/fast on`）で、次の質問・指示から思考なしを指定します。
`/` の補完一覧には `/fast` と `/fast off` の両方を表示します。`/fast ` の後からもオフを選べます。
`/fast` を繰り返してもオンを維持し、オフにするときは `/fast off` を使います。
高速モード中は入力欄に `FAST >`、回答待ち・受信中の状態バーにも `FAST` を表示します。
`/fast off` で、次の依頼から通常の設定へ戻します（思考ONを強制せず、サーバーの既定を使用）。
挨拶だけの場合の既存設定は維持します。ツールを使った後の再応答にも高速モードを適用し、
ツールの利用可否・承認・安全機構は変えません。

切り替え自体はAIに送信せず、履歴・セッションにも保存しません。`/new` ではモードを維持し、
CLIを終了して再起動するとオフに戻ります。`/think` は直前に受信した思考がある場合だけ表示します。
高速モードはサーバーが `chat_template_kwargs.enable_thinking=false` に対応していることが前提です。
履歴要約などの補助処理は従来の設定のままで、通信待ちや本文の生成時間をなくすものではありません。
複雑な依頼では回答品質が変わる場合があり、常に同じ精度や一定時間内の応答を保証するものではありません。

通常モードの共通指示にも、確認できない細かな年号・バージョンなどを繰り返し推測せず、
不確かな点を明示して回答を進める方針を追加しています。重要な事実の検証は引き続き行います。
